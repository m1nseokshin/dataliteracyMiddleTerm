# 🧮 스코어링 모델 결정 기록

명세서 4장의 수식을 구현하기 위한 파라미터와 정규화 방식을 기록합니다.
코드 위치: `src/js/engine/scoring.js`

## 1. 지표 요약

| 기호 | 이름 | 핵심 입력 | 방향 |
| :--- | :--- | :--- | :--: |
| $\hat{T}_{time}$ | 소요 시간 | 역간 주행시간 + 환승 소요시간 | 낮을수록 좋음 |
| $\hat{S}_{congestion}$ | 열차 밀집 스트레스 | 혼잡도 $C(e,t)$, 주행시간 $\Delta d_e$ | 낮을수록 좋음 |
| $\hat{S}_{transfer}$ | 환승 피로도 | 환승거리 $L_k$, 편의시설 $F_k$, 밀집계수 $M(k,t)$ | 낮을수록 좋음 |
| $\hat{P}_{seat}$ | 착석 가능성 | 승차/하차 인원, 혼잡도 | 높을수록 좋음 |

$$S_{total}(R) = w_1 \hat{T}_{time} + w_2 \hat{S}_{congestion} + w_3 \hat{S}_{transfer} - w_4 \hat{P}_{seat}$$

UI 표기: **쾌적도 점수 = 100 − S_total**

## 2. 구현된 파라미터 (src/js/engine/scoring.js `PARAMS`)

| 파라미터 | 값 | 근거 |
| :-- | :-: | :-- |
| α (혼잡 비선형 지수) | 1.5 | 명세서 지정 |
| β₁ / β₂ (환승 시간 / 동선) | 0.7 / 0.3 | 설계 선택. 0.3/0.7로 바꿔도 시나리오 결론 유지 (`sensitivity_report.md`) |
| γ (착석 순유출 계수) | 0.35 | 설계 선택. 0.15, 0.7로 바꿔도 유지 |
| L_k | 환승시간 ÷ 300초 | 환승 **거리** 데이터가 없어 시간으로 대신함 |
| F_k | 0.35·(1−편의시설점수) + 0.65·(경로복잡도÷10) | 편의시설 점수는 대형 환승역이 모두 0.8~1.0이라 변별력이 낮아 경로복잡도에 더 비중 |
| M(k,t) | 0.5 + 환승역 밀집계수(0~1) | 밀집이 0인 시간대에도 환승 부담이 0이 되지 않도록 바닥 0.5 |

**정규화 (고정 범위)**: 대표 출발-도착 쌍 3,852개의 최단 경로에서 지표별 95백분위를 구해 100점 기준으로 삼는다 (`scripts/calibrate_scales.mjs` → `src/data/scales.json`). 후보 경로가 바뀌어도 점수의 의미가 같다. 기준을 넘으면 100으로 자른다.

**종합 점수**: 명세서 `S_total = w1·T + w2·S_c + w3·S_t − w4·P`, UI는 `100 − S_total`. 점수가 0~100에 머물도록 착석 항을 `w4·(100−P)`로 바꿨다(상수 100·w4만 달라 **순위는 동일**). 가중치는 슬라이더 값을 합 1로 정규화하고, 모두 0이면 균등.

**착석 가능성**: 경로 위 지나는 역(도착지 제외)마다 `ΔN = (하차−승차)/(하차+승차+1)`을 구하고 `1 − Π(1 − max(0, γ·ΔN·(1 − C/150)))`.
